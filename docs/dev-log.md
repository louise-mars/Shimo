# 拾墨 — 开发日志

> 记录从 NotePro 到拾墨的完整演进过程

---

## 阶段1：工程分隔

**起点：** 单一 NotePro 项目（Tauri + React）

**决策：** 将桌面版和移动版分离，提取共享代码库

**结果：**
```
NotePro/
├── Desktop/   Tauri + React
├── Mobile/    Capacitor + React
└── Shared/    共享类型、Supabase、同步引擎
```

---

## 阶段2：移动版初始化

**技术选型：**
- Capacitor（跨平台移动端）
- TipTap（富文本编辑器）
- Supabase（云同步）

**初始架构：** 复制桌面版组件，适配移动端

---

## 阶段3：UI 重构（第一次）

**问题：** 初始版本是桌面版的移动端适配，不是真正的移动端设计

**重构方向：** 山水风格 → 后来否定，改为克制极简

**关键决策：**
- 砍掉文件夹系统，改用 #标签
- 笔记列表改为按日期分组的纯文字列表
- 编辑器无工具栏，打开即聚焦
- 搜索独立为一个 tab

---

## 阶段4：产品定位讨论

**核心问题：** "记了之后怎么办？"

**5个核心场景确定：**
1. 灵光一闪 → 3秒落笔
2. 沉浸写作 → 忘记时间
3. 会议记录 → 清晰不费脑
4. 找回旧记忆 → 5秒内找到
5. 睡前回顾 → 今天的我

**设计原则确定：**
- 氛围优先
- 零摩擦入口
- 克制功能（不做文件夹、Block、AI写作）

---

## 阶段6：品牌命名

**从 NotePro → 拾墨**

**命名理由：**
- "拾"：捡起、收集，对应"随手记"的核心场景
- "墨"：呼应山水书法氛围和图标的墨滴设计
- 英文：Shimo

**Slogan：** 拾起片刻，落成秩序

## 阶段9：思维流路径设计

**核心洞察（来自外部建议）：**

拾墨的本质是"思维捕捉-回流系统"，不是笔记软件。

**完整路径：**
想到 → 捕捉 → 结构化 → 存入时间流 → 回看 → 再次激发 → 循环

**三个关键功能：**
1. Widget（不打开 App 也能记录）
2. 第二次激发入口（回看时追加）
3. 今日回顾推送（每晚9点）

## 阶段14：产品评审第二轮反思

**反思方法：** 从"用户会不会真的用这个 app"角度重新审视，而非技术修复角度

**新发现的根本性问题：**
1. 首次使用体验完全空白 — 新用户不知道 app 能做什么
2. 没有回收站 — 误删不可恢复，数据安全底线缺失
3. 桌面版没有语音输入 — 核心功能在桌面端缺失
4. 加密笔记忘记 PIN 无出路 — 用户可能被永久锁在外面
5. 同步冲突静默覆盖 — 多设备编辑会丢数据
6. 没有笔记排序选项 — 50+ 笔记后找笔记困难
7. 置顶笔记无视觉标记 — 功能存在但用户看不到
8. 深色模式切换无过渡 — 瞬间变色体验差
9. 移动版无下拉刷新 — 违反用户习惯
10. 移动版编辑器无图片支持 — 最需要拍照的平台反而不支持
11. 标签不能重命名/合并 — 标签管理能力缺失
12. 桌面版无今日回顾 — 核心功能只在移动端

**设计方案修正：**
- P0-1 移动版工具栏从"6个元素挤一行"改为"← 和 ⋯ 两个按钮"
- P0-4 删除弹窗副标题改为"可在回收站恢复"
- P1-1 设计系统从 P2 提升到 P1（后续修复都需要参考规范）
- P1-3 笔记列表三行结构增加紧凑/宽松切换选项

**优先级重排原则：**
- P0 = 决定用户留存（没有这些，用户试一次就走）
- P1 = 决定用户满意度（有这些，用户觉得好用）
- P2 = 决定用户口碑（有这些，用户会推荐给别人）

**最终任务数：** P0 × 5 + P1 × 11 + P2 × 12 = 28 项

- **冲突 UI 暴露** — `useSync` 新增 `SyncConflict` 接口（local/remote Note 对），`conflicts` 状态和 `dismissConflicts` 回调，供 UI 层展示冲突解决面板

### 关键设计决策

**命令面板 vs 快捷键：** 所有功能同时支持命令面板和快捷键。命令面板是"发现"入口（新用户探索功能），快捷键是"效率"入口（老用户秒开）。

**双向链接 vs 标签：** 标签是分类工具（一对多），双向链接是关联工具（多对多）。两者互补，不替代。标签用于"这是什么类型的笔记"，链接用于"这和哪些笔记有关"。

**配色方案 vs 主题：** 配色是浅色模式的个性化层，主题（light/dark/system）是底层切换。配色不影响深色模式，避免组合爆炸。

**笔记嵌入 vs 复制粘贴：** 嵌入是"引用"（源笔记变化时嵌入自动更新），复制是"快照"（独立副本）。嵌入适用于"项目目标""会议决议"等经常被多处引用的内容。

### 技术亮点

- **WikiLink 用 Decoration 而非 Mark** — 不修改文档 JSON 结构，`[[title]]` 以纯文本存储，渲染层通过正则匹配加装饰。优点：zero schema migration，与 Markdown 导出天然兼容。
- **NoteEmbed 用 TipTap Node + ReactNodeViewRenderer** — 块级节点需要复杂渲染（卡片布局 + store 访问），React NodeView 是 TipTap 官方推荐方案。
- **配色方案用 CSS custom properties 运行时覆盖** — 零组件重渲染成本，切换瞬间生效。
- **精美 HTML 导出自渲染 TipTap JSON** — 不依赖 TipTap 的 HTML 序列化（有外部依赖），自己实现轻量 JSON → HTML 转换器。
