## 一、视觉风格

### 设计关键词
克制 · 留白 · 有思考感 · 不像软件，更像一页随时可以写字的纸

### 颜色体系

```
主色（核心）
  墨黑：#1C1C1E（偏柔和，非纯黑）

背景
  浅色：米白 #F7F6F3
  深色：深灰 #121212

唯一强调色
  朱砂红：#B5341A（品牌色、操作色）
  深朱砂：#8C2614（按钮、激活状态）

功能色
  成功：#4A7C6F
  危险：#C0392B
  警告：#B8860B
```

**原则：颜色不超过3种主色**

### 字体体系

```
标题 / 笔记内容：Noto Serif SC（书写感）
界面文字：Noto Sans SC（可读性）
数字 / 英文：Inter（精准）
代码：JetBrains Mono
```

**策略：标题有气质，正文绝对清晰**

### 间距与圆角

```
左右 padding：16–20px
行距：1.6–1.9
圆角：6–8px（克制，不过度圆润）
```

## 三、交互设计

### 语音输入（核心交互）

```
方案：录音 + 在线 ASR（不依赖 Google 服务）

流程：
1. 点击 🎙 → MediaRecorder 开始录音
2. 显示计时 + 红色脉冲动画
3. 点击 ⏹ 停止 → 音频上传到 ASR 服务
4. 显示"识别中…" → 返回文字 → 插入编辑器

ASR 服务（Whisper API 兼容格式）：
- 硅基流动（国内直连，推荐）
- 阿里百炼
- Groq（需翻墙）

未配置时：
- 底部显示"点击配置语音识别 →"
- 点击麦克风 → 自动跳转设置页

有 AI 时：录音 → ASR → AI 结构化 → 插入标题+内容+标签
无 AI 时：录音 → ASR → 直接插入文字
```

### 沉浸模式

```
触发：停止输入15秒
效果：
  - 顶部工具栏隐藏
  - 背景渐变（根据时间：晨/昼/暮/夜）
  - 落花动画（春天樱花/秋天枫叶）
  - 标题淡显在顶部
  - 底部"轻触退出"提示

退出：轻触屏幕任意位置
```

### 时间感知氛围

| 时间 | 背景 | Placeholder |
|------|------|-------------|
| 5–9点 | 暖橙渐变 | 晨光初照，写下此刻… |
| 9–17点 | 宣纸白 | 记录此刻… |

### 日程识别

```
触发：停止输入1.5秒后检测
识别：明天下午3点 / 下周一 / 5月1日 等
弹出：底部确认卡片（不打断写作）
操作：点"加入日历" → 写入系统日历 → 知天自动显示
```

```
笔记列表每行右侧有"+"按钮
点击 → 打开该笔记 → 自动触发语音输入
目的：回看时产生新想法，一键追加
```

## 十一、v1.0.1 体验打磨 — 详细设计方案

> 日期：2026年4月 | 状态：大部分已实现（第二轮修订）

### P0 — 决定用户留存

#### P0-1：首次使用引导

**现状问题：** 新用户安装后看到空列表 + "落笔成文"按钮，不知道 app 能做什么、语音在哪里、标签怎么用、AI 功能是否存在。

**设计方案：** 首次启动时自动创建一条"欢迎笔记"，用笔记本身演示功能：

```
标题：欢迎来到拾墨
内容：
  拾墨是你的思维捕捉工具。在碎片中，建立秩序。

  试试这些：
  · 直接开始打字，内容会自动保存
  · 输入 #标签 自动识别并归类
  · 输入 / 唤出命令菜单（标题、列表、代码块…）
  · Ctrl+N 新建笔记，Ctrl+T 选择模板
  · Ctrl+/ 查看所有快捷键

  准备好了？删除这条笔记，开始你的记录。
标签：[欢迎, 教程]
```

桌面版额外在底部显示快捷键提示卡片（3秒后淡出）：`Ctrl+N 新建 | Ctrl+D 主题 | ? 帮助`

**设计理由：** Bear 首次打开有欢迎笔记，Notion 有交互引导。用产品自身演示功能是最低摩擦的引导方式。

---

#### P0-2：回收站

**现状问题：** 删除不可逆，无回收站、无撤销删除。误删重要笔记永久丢失。

**设计方案：**

Note 类型新增字段：
```typescript
deletedAt: number | null  // null = 未删除，有值 = 软删除时间戳
```

逻辑：
- 删除操作改为设置 `deletedAt = Date.now()`，不真正移除
- 列表过滤 `deletedAt !== null` 的笔记
- 侧边栏"视图"区新增"回收站"入口，显示已删除笔记
- 回收站内可"恢复"（清除 deletedAt）或"永久删除"
- 超过 30 天的自动永久删除（每次启动时清理）

**设计理由：** Apple Notes、Bear、Notion 都有回收站。这是数据安全的基本底线。

---

#### P0-3：移动版编辑器工具栏简化

**现状问题：** 只有返回、图谱、删除三个按钮，功能残缺。

**设计方案（修订）：**
```
┌──────────────────────────────┐
│ ← 返回    ● 已保存      ⋯  │
└──────────────────────────────┘
```

只保留两个按钮：`← 返回` 和 `⋯ 更多`。

`⋯` 点击弹出底部 ActionSheet：
```
┌──────────────────────────────┐
│  ☆ 收藏                     │
│  🔒 加密                    │
│  👁 隐藏                    │
│  📤 分享                    │
│  📝 新建笔记                │
│  ──────────────────────      │
│  🗑 删除          （红色）   │
│  ──────────────────────      │
│  取消                        │
└──────────────────────────────┘
```

删除用红色文字，与其他操作用分割线隔开。

**设计理由（修订）：** 之前方案把 6 个元素挤在一行，iPhone SE（320px）上会拥挤。只保留 `←` 和 `⋯` 更符合"克制"原则，也是 Apple Notes 移动版的做法。

---

#### P0-4：删除自定义确认弹窗

**现状问题：** 使用浏览器原生 `confirm()`，样式丑陋且破坏沉浸感。

**设计方案：**
```
┌──────────────────────────────┐
│                              │
│     确定删除这条笔记？       │
│     删除后可在回收站恢复。   │
│                              │
│   [取消]        [删除]       │
│                              │
└──────────────────────────────┘
```

- 居中模态弹窗，半透明遮罩
- 副标题改为"删除后可在回收站恢复"（因为有回收站了）
- 删除按钮红色背景，取消按钮灰色
- 点击遮罩 / Esc 键关闭

**设计理由：** 自定义弹窗保持品牌一致性。"可在回收站恢复"降低用户焦虑。

---

#### P0-5：加密 PIN 错误次数限制

**现状问题：** PIN 可无限尝试，暴力破解 4 位数字只需 10000 次。

**设计方案：**
```
1-2 次错误：显示"PIN 码错误"，可立即重试
第 3 次错误：锁定 60 秒，显示倒计时
第 6 次错误：锁定 5 分钟
第 10 次错误：锁定 30 分钟

存储：localStorage shimo-pin-attempts = { count, lockedUntil }
成功解锁后重置计数
```

**设计理由：** iOS 标准做法。让暴力破解的时间成本高到不值得。

---

### P1 — 决定用户满意度

#### P1-1：设计系统文档化 + 跨平台样式统一

**现状问题：** 桌面版和移动版 CSS 变量有微妙差异，间距体系不统一。

**设计方案：** 创建 `Shared/src/styles/tokens.css` 作为唯一真相源，两端 `@import`。同时创建 `docs/design-system.md` 记录规范。

```css
:root {
  --space-1: 4px; --space-2: 8px; --space-3: 12px;
  --space-4: 16px; --space-5: 20px; --space-6: 24px; --space-8: 32px;
  --text-xs: 10px; --text-sm: 12px; --text-base: 14px;
  --text-lg: 16px; --text-xl: 20px; --text-2xl: 24px;
  --accent-light: rgba(181, 52, 26, 0.12);
}
```

**设计理由：** 从 P2 提升到 P1，因为后续所有修复都需要参考统一规范。没有规范就开始修，修完还是不一致。

---

#### P1-2：保存状态始终可见

**设计方案：** 三态循环，12px，始终显示在工具栏左侧：
- `● 编辑中`（灰色）→ `● 保存中`（橙色脉冲）→ `✓ 已保存`（绿色，3秒后回到编辑中）

**设计理由：** 参考 Google Docs。用户对数据安全有天然焦虑。

---

#### P1-3：搜索高亮加深

**设计方案：** 透明度 0.1 → 0.2，匹配文字加粗（font-weight: 500），增加 padding。

**设计理由：** 搜索核心价值是快速定位，高亮不明显等于功能打折。

---

#### P1-4：同步失败具体错误信息

**设计方案：** 根据错误类型显示不同提示（网络错误/登录过期/频率限制/通用失败），点击可重试。

**设计理由：** 用户需要知道该做什么（检查网络/重新登录/等待）。

---

#### P1-5：笔记排序选项

**现状问题：** 列表只按更新时间排序，50+ 笔记后找特定笔记困难。

**设计方案：** 列表顶部搜索框旁添加排序按钮，支持：更新时间（默认）、创建时间、标题字母序、字数。

**设计理由：** 所有主流笔记 app 都支持多种排序。

---

#### P1-6：忘记 PIN 恢复流程

**现状问题：** 忘记 PIN 后，如果 App 锁也开着，用户连设置都进不去。

**设计方案：** PIN 输入界面底部添加"忘记 PIN？"链接，点击后：
- 如果已登录 Supabase：要求重新输入邮箱验证
- 如果未登录：直接重置 PIN（清除 localStorage），但加密笔记内容不可恢复

**设计理由：** 任何锁定机制都必须有恢复路径，否则用户会被永久锁在外面。

---

#### P1-7：置顶笔记视觉标记

**现状问题：** Note 有 `pinned` 字段，但列表中置顶笔记和普通笔记看起来一样。

**设计方案：** 置顶笔记标题前显示小图钉图标（📌 或 SVG），且始终排在分组顶部。

**设计理由：** 置顶功能如果没有视觉反馈，用户不知道哪些是置顶的。

#### P1-8：深色模式切换过渡动画

**现状问题：** 切换主题时整个界面瞬间变色，视觉冲击大。

**设计方案：**
```css
html { transition: background-color 200ms ease, color 200ms ease; }
html * { transition: background-color 200ms ease, color 200ms ease, border-color 200ms ease; }
```

**设计理由：** 200ms 过渡让切换感觉"自然"而非"闪烁"。

#### P1-10：移动版下拉刷新同步

**现状问题：** 用户习惯下拉刷新，当前只能去设置页点同步。

**设计方案：** 笔记列表页支持下拉手势，触发 `triggerSync()`，显示刷新动画。

#### P1-11：同步冲突提示

**现状问题：** Last-Write-Wins 策略，多设备同时编辑会静默覆盖，用户丢内容不知道。

**设计方案：** 合并时检测到同一笔记的远程 `updatedAt` 和本地 `updatedAt` 都比上次同步时间新，弹出提示："此笔记在其他设备上有更新"，提供"保留本地/保留远程/保留两者（创建副本）"三个选项。

**设计理由：** 数据不丢失是底线。即使 Last-Write-Wins 是简单方案，也应该在冲突时告知用户。
